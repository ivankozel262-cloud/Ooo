# Система — план проекта

17 октября 2026

## Идея

**Система — живой механизм, который подстраивается под задачи и умнеет от опыта: неизменное ядро, сменные миссии и органы.** Весь код пишет Claude Code, а ты ставишь задачи и наблюдаешь; механизм растёт сезонами, без дедлайна.

Ядро делает одно и то же для любой задачи: собирает данные, сохраняет, находит в них важное и сообщает. Миссия говорит ему, что именно: откуда брать данные, что считать сигналом и куда писать. Сменил сферу — не переписываешь систему, а добавляешь миссию; простую Claude Code соберёт по твоему описанию словами.

Разовые задачи вроде «найди, разбери, составь план» уходят агенту, а его выводы ложатся в память. Раз в неделю система сама ищет у себя слабые места: улучшатель предлагает правку, критик её проверяет, а решаешь ты. Всё это видно на рентгене — живой схеме-дереве, — а летопись склеивает рост в видео.

Примеры миссий на одном движке:

- **Рынок** — акции Мосбиржи: всплеск объёма плюс негативная новость о компании дают сигнал.
- **Планета** — землетрясения по всему миру на карте; это тестовая миссия, потому что данные бесплатные и свежие.
- **GitHub-радар** — репозитории, которые за неделю резко набирают звёзды.
- **Наука** — новые статьи на arXiv по твоей теме.
- **Цены** — товар или сырьё подешевели больше чем на 15%.

Мозг у системы сменный: Claude, локальная модель или вовсе без AI. Тело — сборщики, память, рентген — своё и работает даже без Claude. Кодовое имя выберем позже; один из кандидатов — «Аргус», стоглазый великан из греческих мифов, который видел всё вокруг.

## Как устроена

**Система устроена как организм: всё, что она узнаёт, превращается в событие одного формата, а органы общаются только через шину событий.** Поэтому новый орган или миссия подключается, не ломая остальные.

**Мозг — сменный: Claude, локальная модель или без AI**
- **Диспетчер** — решает, куда отправить запрос: миссия, агент, конструктор.
- **Агент** — «найди, разбери, составь план»; ищет в интернете и в памяти.
- **Самоанализ** — улучшатель предлагает правку, критик и тесты решают.
- **Строитель** — единственное место, откуда система зовёт Claude Code править свой код: иммунитет, улучшатель, критик; всегда в отдельной git-ветке.

**Тело — своё, работает и без Claude**
- **Корни: сборщики** — тянут данные из источников: биржа, новости, USGS, GitHub.
- **Ствол: шина и хранилище** — всё превращается в события одного формата с отметкой времени.
- **Кольца: память опыта** — нормы, исходы сигналов, похожие случаи из прошлого.
- **Ветви: миссии** — что отслеживать; новая область — это новая миссия.
- **Иммунитет** — сломался сборщик, Claude Code чинит, тесты решают: включить или откатить.
- **Входящие** — сигналы и отчёты на рентгене и в папке reports/.

**Рентген и летопись** — живая схема-дерево, кадр после каждого этапа, видео роста, журнал решений.

Связи: мозг отдаёт телу задачи и выводы, тело отдаёт мозгу данные и ошибки. Если мозг отключить, тело продолжит работать. Событие — это источник, время, объект, тип, числа, текст и теги.

### Ядро: маленькое, но с прочными контрактами

**В ядро кладётся как можно меньше, зато продуманно: тогда его можно заменить, не ломая остальную систему.** Всё, что может устареть, — база, модель AI, источники, интерфейс — живёт в сменных модулях.

1. **Контракт события с номером версии.** Поля только добавляются, у каждого события есть след — путь через модули; по нему рисуется рентген.
2. **Маленькие стабильные интерфейсы** для плагинов, мозга, строителя, хранилища и планировщика; всё внешнее подключается через адаптеры.
3. **Тесты-контракты**, которые обязан проходить любой модуль и любое будущее ядро.
4. **Миграции данных** — переход базы на новую версию без потерь.
5. **Наблюдаемость** — основа рентгена и самоанализа.

При замене ядра остаются миссии, плагины, база с опытом, рентген и летопись: они связаны с ядром только через контракты. Замена идёт приёмом «фикус-душитель»: новое ядро растёт рядом со старым, проходит те же тесты и забирает модули по одному, сначала в тени. Позже систему можно сделать MCP-сервером, чтобы Claude Code и другие AI-ассистенты обращались к её памяти и инструментам.

## Стек и подготовка MacBook

**Достаточно одной команды установки и входа в аккаунт Pro, остальное Claude Code поставит сам.** Claude Code работает на macOS 13 и новее и требует от 4 ГБ памяти.

1. Открой «Терминал» и установи Claude Code: `curl -fsSL https://claude.ai/install.sh | bash`
2. Открой новое окно терминала и проверь установку: `claude --version` должна вывести номер версии.
3. Проверь, что переменная ключа пустая: `echo $ANTHROPIC_API_KEY` ничего не выводит. Если ключ задан, Claude Code будет списывать деньги с API, а не тратить подписку.
4. Создай папку проекта и зайди в неё: `mkdir -p ~/sistema/docs && cd ~/sistema`
5. Положи в корень `~/sistema` файл `CLAUDE.md`, а этот план — в `~/sistema/docs/plan.md`.
6. Запусти `claude`, войди аккаунтом Pro через браузер и вставь промпт этапа 0.

| Инструмент | Зачем |
| --- | --- |
| Python 3.12 и uv | язык системы и менеджер пакетов |
| SQLite | база событий, встроена в Python |
| FastAPI и D3.js | рентген: локальная страница с живым деревом |
| Playwright и ffmpeg | кадры, запись рентгена и видео роста |
| git | история, откат, ветки и worktree для самоулучшений |
| launchd | держит `sistema serve` запущенным на маке (на Linux — systemd) |
| Ollama (по желанию) | локальный мозг, работает без интернета |

## Бюджет на Pro

**Подписки Pro хватит, если строить по одному этапу за сессию: работающая система почти не тратит AI.**

- Лимиты Pro общие для чата и Claude Code: есть лимит на пятичасовую сессию и недельный лимит. Остаток видно командой `/usage` внутри Claude Code.
- «1 миллион токенов» — не бюджет, а окно контекста: сколько помещается в одну сессию. Модель по умолчанию на Pro — Opus 5.5 с окном 1M. Чем длиннее сессия, тем тяжелее каждое сообщение: оно тянет за собой всю переписку.
- У работающей системы лимиты тратят только AI-слой, агент, иммунитет и еженедельный самоанализ. Сбор данных, детекторы, нормы и рентген работают без AI.

Как экономить:

1. Один этап — одна сессия, между задачами `/clear`.
2. Сложное начинай с режима плана: Shift+Tab, пока не включится plan mode, потом «ок».
3. Рутину отдавай Sonnet: `/model sonnet`. Или `/model opusplan`: Opus планирует, Sonnet пишет код.
4. Держи `CLAUDE.md` короче 200 строк.
5. После перерыва больше часа начинай новую сессию: кэш на подписке живёт час, и длинная переписка обработается заново.
6. Упёрся в лимит — дождись сброса, этап не сгорит.

## Сезоны и вехи

**Дедлайна нет: механизм растёт сезонами, и каждый сезон заканчивается работающей системой и видео.** Сезон — это 2–4 вечера; темп выбираешь сам, этапы не сгорают.

1. **Росток** (этапы 0–3) — ядро, первая миссия «Планета», рентген-дерево, летопись, бэкап и автозапуск. Веха: на рентгене видно, как события бегут по дереву, склеено первое видео, система сама запускается при входе в мак.
2. **Корни** (этапы 4–6) — миссия «Рынок», «Входящие», конструктор миссий, иммунитет. Веха: новая миссия собирается по описанию словами, а сломанный сборщик чинится сам.
3. **Мозг** (этапы 7–8) — сменный мозг, AI-слой, агент и диспетчер. Веха: задача «найди, разбери, составь план» возвращает отчёт со ссылками и может стать миссией.
4. **Опыт** (этапы 9–11) — нормы, исходы, обратная связь, отбор правил, память случаев. Веха: каждое правило сравнивается со случайным угадыванием, слабые отключаются.
5. **Самоанализ** (этапы 12–13) — улучшатель и критик, теневой запуск. Веха: правка проходит путь «улучшатель → критик → тесты → твоё решение».
6. **Дальше** — новые миссии и органы, перенос на Mac mini или сервер, личное пространство на локальном мозге, MCP-сервер, твой собственный код.

## Сезоны 1–2: пошагово с промптами

**Каждый этап — одна сессия: запусти `claude` в папке проекта, вставь промпт, прочитай план и ответь «ок» или поправь.** Между этапами — `/clear`. Пункты «Увидишь» и «Готово, когда» показывают, что этап действительно завершён.

### Этап 0. Подготовка

**Увидишь:** Claude Code проверит мак, поставит недостающее и создаст скелет проекта. Если для установки понадобятся Homebrew или пароль от мака, он скажет, что и где ввести.

**Готово, когда:** есть первый коммит, и Claude Code объяснил структуру.

```text
Прочитай CLAUDE.md и docs/plan.md. Этап 0 — подготовка.
Проверь, что на маке есть git, uv с Python 3.12+ и ffmpeg. Чего нет — покажи команды установки и поставь после моего «ок».
Создай git-репозиторий, .gitignore (data/, backups/, chronicle/, .env), структуру папок из CLAUDE.md, файлы docs/decisions.md и docs/progress.md. Сделай первый коммит.
Если я дам адрес приватного репозитория, подключи его как remote.
В конце объясни мне структуру проекта простыми словами.
```

### Этап 1. Ядро и миссия «Планета»

**Увидишь:** первые настоящие события — землетрясения со всего мира за последний час.

**Готово, когда:** `uv run sistema events --last 1h` показывает землетрясения, а тесты зелёные.

```text
Этап 1 — ядро. Сначала покажи план и дождись моего «ок».
1) Модель Event по CLAUDE.md, с версией контракта и trace_id.
2) Хранилище SQLite через адаптер: сохранить события без дублей, выбрать за период. Миграции — в migrations/.
3) Шина событий (внутри процесса, через адаптер), интерфейсы плагинов четырёх видов (collector, enricher, detector, output) и реестр, который сам находит плагины в plugins/.
4) Планировщик, который запускает миссию по её расписанию.
5) Первый сборщик — землетрясения USGS (фид all_hour.geojson, обновляется каждую минуту) и миссия missions/planet.yaml.
6) CLI `sistema` (точка входа в pyproject, работает как `uv run sistema …`) с командами `run planet` и `events --last 1h`.
7) Тесты pytest, сеть в тестах замокана; тесты-контракты для плагинов и хранилища — в tests/contracts/.
После каждого шага — коммит и запись в журнал решений.
```

### Этап 2. Рентген-дерево

**Увидишь:** живое дерево в браузере — корни, ствол, ветви и бегущие частицы событий.

**Готово, когда:** страница http://localhost:8000 показывает «Планету» в реальном времени.

```text
Этап 2 — рентген. Сделай локальную страницу: FastAPI и одна HTML-страница на D3.js, тёмный стиль «центр управления». Сервер слушает только localhost.
Рисуй систему деревом: корни — сборщики, ствол — ядро и хранилище, кольца на стволе — память опыта (пока пусто), ветви — миссии, листья — сигналы.
События бегут частицами от корней к ветвям по их trace_id. У каждого модуля счётчик и статус: работает, ошибка, спит.
Клик по любой части показывает последние события, ошибки, код модуля и его объяснение из журнала решений.
Дерево строится само из реестра плагинов и миссий: новый модуль — новая ветвь или корень без правок рентгена.
```

### Этап 3. Летопись, бэкап и автозапуск

**Увидишь:** первое видео «Как росла Система», а после перезагрузки мака система поднимается сама.

**Готово, когда:** в chronicle/ лежат кадры, видео собирается одной командой, бэкап сделан, а `sistema serve` запускается при входе.

```text
Этап 3 — летопись, бэкап и автозапуск.
1) Команда `sistema snapshot`: Playwright открывает рентген и сохраняет кадр в chronicle/ с датой и номером этапа.
2) Команда `sistema chronicle`: ffmpeg склеивает кадры в видео «Как росла Система» с подписями этапов.
3) Команда `sistema record 30`: запись 30 секунд живого рентгена в видео.
4) Команда `sistema backup`: git bundle, копия базы и chronicle/ в backups/ и во второе место, которое я укажу; каждый день через планировщик.
5) Команда `sistema serve`: один процесс с планировщиком и рентгеном. `sistema autostart on` ставит launchd-агента, который запускает его при входе и перезапускает при падении.
6) Команда `sistema install`: установка всего нужного на новом компьютере.
Сделай первый кадр, первое видео и первый бэкап.
```

### Этап 4. Миссия «Рынок» и «Входящие»

**Увидишь:** вторую ветвь с котировками и новостями, а сигналы — во «Входящих».

**Готово, когда:** детекторы находят всплески объёма, и сигналы видны на рентгене и в reports/.

```text
Этап 4 — миссия «Рынок». Ядро не трогай; если без этого никак — объясни почему и дождись «ок».
1) Сборщик MOEX ISS: дневные и 10-минутные свечи с объёмом для 10 ликвидных акций из конфига. Бесплатные данные идут с задержкой — это нормально.
2) Сборщик новостей из RSS деловых СМИ: адреса найди и проверь сам.
3) Детекторы: всплеск объёма (z-оценка больше 3 относительно 20 дней), падение цены больше 4% за день, связка «всплеск + новость о компании в тот же день».
4) Выход «Входящие»: сигналы и отчёты на рентгене и в reports/.
5) Миссия missions/market.yaml, кадр летописи.
```

### Этап 5. Конструктор миссий

**Увидишь:** новая ветвь вырастает по одной фразе.

**Готово, когда:** «GitHub-радар» и «Наука» собраны без единой правки ядра.

```text
Этап 5 — конструктор. Цель: новая область без кода в ядре.
1) Формат миссии YAML: сборщики, параметры, детекторы, расписание, выходы. Переведи на него обе миссии.
2) Универсальные сборщики: rss, json_api (адрес и путь к полям), page_watch (изменения на странице).
3) Универсальные детекторы: threshold, zscore, trend, keyword, combo.
4) Skill /new-mission: я описываю словами, что отслеживать, ты создаёшь YAML (новый плагин — только если без него никак), прогоняешь тест и показываешь первые события.
Затем сам создай через /new-mission две миссии: «GitHub-радар» (репозитории, которые за неделю набрали больше 500 звёзд) и «Наука» (новые статьи arXiv по теме, которую я назову).
```

### Этап 6. Иммунитет

**Увидишь:** корень краснеет, система зовёт Claude Code, и вскоре он снова зелёный.

**Готово, когда:** нарочно сломанный сборщик чинится сам или изменение откатывается.

```text
Этап 6 — иммунитет. Сделай builder/ — адаптер, через который система зовёт Claude Code править свой код. Если сборщик падает 3 запуска подряд:
1) Отключи его и сохрани ошибку, пример входных данных и код плагина.
2) Через builder/ запусти `claude -p` в отдельной git-ветке и отдельном git worktree, чтобы не мешать работающей системе. Читать можно весь проект, править — только этот плагин и его тесты. Вход по подписке (без --bare), явный --allowedTools, без запросов разрешений (--permission-prompts none), ответ в JSON.
3) Прогони все тесты: зелёные — влей ветку, перезапусти плагин и запиши в журнал; красные — удали ветку и напиши во «Входящие».
4) Не больше 2 попыток в сутки на плагин; всё видно на рентгене.
Проверь: в тестовом режиме сломай формат ответа USGS и покажи, как система чинит себя.
```

## Сезоны 3–5: мозг, опыт, самоанализ

**Здесь система получает мозг, учится на опыте и начинает улучшать сама себя, но каждое изменение проходит отбор.**

### Этап 7. Сменный мозг и AI-слой

**Увидишь:** на стволе загорается AI-слой, а новости превращаются в карточки.

**Готово, когда:** одна и та же новость разобрана тремя мозгами, и есть таблица сравнения.

```text
Этап 7 — сменный мозг. Сделай интерфейс Brain с тремя реализациями:
- claude: `claude -p` с ответом по JSON-схеме (флаги --output-format json и --json-schema, вход по подписке, без --bare);
- local: локальная модель через Ollama, если она стоит на маке;
- none: правила и словари без AI.
Мозг выбирается в конфиге; по умолчанию local или none, claude — только для важного. Модели вызываются только из brain/ и builder/.
Затем AI-слой: обогатитель превращает новость в {компания, тип события, тон от −1 до 1, сила 0–1, суть одной фразой}. Кэш по хэшу текста, счётчик вызовов на рентгене.
Сравни три мозга на 20 новостях и покажи таблицу.
```

### Этап 8. Агент и диспетчер

**Увидишь:** вводишь задачу, и на рентгене видно, как она идёт через диспетчер к агенту и обратно.

**Готово, когда:** задача «найди, разбери, составь план» возвращает отчёт со ссылками, а агент предлагает превратить её в миссию.

```text
Этап 8 — агент и диспетчер.
1) Команда `sistema ask "…"` и поле ввода на рентгене.
2) Диспетчер решает, куда отправить запрос: «следи за…» — в конструктор миссий; «найди / разбери / составь план» — агенту; вопрос о накопленных данных — в память.
3) Агент — через brain/: `claude -p` с поиском в интернете (инструменты WebSearch и WebFetch) и доступом к базе системы только на чтение. Ответ — отчёт со ссылками на источники; он сохраняется в память и во «Входящие».
4) Если задача повторяющаяся, агент предлагает новую миссию, а я подтверждаю.
5) Дневной лимит вызовов агента — в конфиге, расход виден на рентгене.
```

### Этап 9. Нормы и исходы

**Увидишь:** на стволе появляются кольца опыта, а пороги детекторов начинают сдвигаться сами.

**Готово, когда:** у каждого правила есть карточка «точность против случайного».

```text
Этап 9 — опыт.
1) Нормы: каждый детектор хранит, что обычно для его источника: по часам, дням недели, со временем — по сезонам. Пока данных мало, он только наблюдает (период привыкания).
2) Исходы: через N дней после сигнала система проверяет, что случилось. Для рынка — изменение цены через 1, 3 и 5 дней.
3) Карточка правила: сколько сигналов, сколько сбылось, сравнение со случайными сигналами в те же дни и пометка, хватает ли сигналов для вывода (например, не меньше 20).
4) Раз в неделю — новое кольцо опыта на рентгене с итогами недели.
Важно: правила видят только прошлое, никакого заглядывания в будущее.
```

### Этап 10. Обратная связь и отбор правил

**Увидишь:** слабые правила желтеют и опадают, новые появляются почками.

**Готово, когда:** отключённые и новые правила видны в журнале вместе с причинами.

```text
Этап 10 — обратная связь и отбор.
1) Кнопки «полезно» и «шум» у каждого сигнала во «Входящих»; система подстраивает пороги по этим отметкам.
2) Правило, которое при достаточном числе сигналов 4 недели подряд не лучше случайного, отключается (не удаляется) с записью причины.
3) Раз в неделю Claude Code предлагает 3 правила-кандидата; кандидат включается, только если на истории он лучше случайного.
4) На дереве видно опадающие листья и новые почки.
```

### Этап 11. Память похожих случаев

**Увидишь:** у нового сигнала появляется карточка «похожее было N раз, и вот чем кончилось».

**Готово, когда:** память находит похожие случаи для любой миссии.

```text
Этап 11 — память случаев. Сохраняй каждый сигнал как случай: признаки, контекст, исход.
Для нового сигнала находи 5 самых похожих из прошлого и показывай, чем они кончились.
Сделай это одинаково для всех миссий — через общие признаки события, без кода под каждую область.
```

### Этап 12. Самоанализ: улучшатель и критик

**Увидишь:** раз в неделю во «Входящие» приходит отчёт «что во мне плохо и что предлагаю» вместе с возражениями критика.

**Готово, когда:** правка проходит путь «улучшатель → критик → тесты → твоё решение».

```text
Этап 12 — самоанализ. Раз в неделю, по расписанию планировщика, через builder/:
1) Система собирает свою статистику: ошибки, медленные модули, шумные правила, расход лимитов.
2) Улучшатель — запуск `claude -p` — читает код и статистику и готовит до 3 правок, каждую в своей git-ветке и отдельном worktree, с тестами и объяснением.
3) Критик — отдельный запуск `claude -p` с ролью строгого ревьюера — проверяет каждую правку: что может сломаться и не хитрит ли она, например не отключает ли проверку ради красивых цифр.
4) Во «Входящие» приходит отчёт: правка, мнение критика, результаты тестов. Мелкий ремонт плагинов вливается сам после тестов, изменения ядра — только после моего «ок».
```

### Этап 13. Теневой запуск

**Увидишь:** рядом с ветвью растёт её полупрозрачная «тень», и видно, какая версия работает лучше.

**Готово, когда:** новая версия заменяет старую только по итогам сравнения.

```text
Этап 13 — теневой запуск. Новая версия детектора или обогатителя сначала работает параллельно со старой на тех же данных, но её сигналы никуда не уходят.
Через неделю сравни их по карточкам правил. Новая заменяет старую, только если она лучше, — с записью в журнал решений.
Покажи тени на рентгене полупрозрачными ветвями.
```

## Стартовый CLAUDE.md

**Этот файл — память Claude Code о проекте: он загружается в начале каждой сессии.** Он также лежит отдельным файлом рядом с этим планом — положи его в корень папки `~/sistema` перед этапом 0 и держи коротким.

```markdown
# Система

Живой механизм наблюдения: неизменное ядро, сменные миссии и органы. Я не программист и учусь, наблюдая: ты пишешь весь код, я ставлю задачи и принимаю решения. Объясняй коротко, простыми словами, по-русски.

Полный план с этапами — docs/plan.md. Текущий этап и что уже сделано — docs/progress.md: читай его в начале сессии и обновляй в конце этапа.

## Архитектура
- Всё, что система узнаёт, — Event: id, schema_version, trace_id, source, time, entity, kind, values (числа), text, tags, geo (необязательно).
- Ядро (core/): реестр плагинов, планировщик, шина событий, хранилище через адаптер (сейчас SQLite). Ядро ничего не знает о конкретных областях.
- Плагины (plugins/): collector → enricher → detector → output.
- Миссии (missions/*.yaml) говорят ядру, какие плагины запускать и с какими параметрами.
- Мозг (brain/): сменный — claude, local или none. Думает о данных: AI-слой и агент.
- Строитель (builder/): единственное место, откуда система зовёт Claude Code править собственный код: иммунитет, улучшатель, критик.
- Память (memory/): нормы, исходы сигналов, похожие случаи.
- Рентген (xray/): живая схема-дерево; кадры и видео — в chronicle/.
- Входящие: сигналы и отчёты на рентгене и в reports/; Telegram — по желанию, отдельным output-плагином.
- Журнал решений: docs/decisions.md — что и зачем сделано, простыми словами.

## Ядро
- Ядро минимальное: только контракты и механика (реестр, шина, планировщик). Всё предметное и всё, что может устареть, — в плагинах и адаптерах.
- Контракт события версионирован: поля только добавляются. trace_id — путь события через модули, его читает рентген.
- Внешнее — только через адаптеры: storage, brain, builder, scheduler, bus.
- Тесты-контракты в tests/contracts/: их проходит любой плагин, адаптер и будущее ядро.
- Миграции базы — скрипты в migrations/, без потери данных.
- Замена ядра — только «фикусом-душителем»: новое рядом со старым, теневой режим, перенос модулей по одному.

## Правила
- Сначала план и моё «ок», потом код. Маленькие шаги, коммит после каждого.
- У каждого плагина есть тесты; сеть в тестах замокана.
- Ядро меняется, только если иначе нельзя, с объяснением и моим «ок».
- Модели вызываются только из brain/ и builder/.
- Правки, которые система предлагает сама: отдельная git-ветка в отдельном git worktree, чтобы не трогать работающую систему → критик → тесты → моё решение. Мелкий ремонт плагинов вливается сам после зелёных тестов, изменения ядра — только с моим «ок».
- Фоновые запуски `claude -p`: без --bare (вход по подписке), с явным списком --allowedTools и без запросов разрешений (--permission-prompts none). Всё, что не разрешено явно, запрещено.
- Правила видят только прошлое: никакого заглядывания в будущее. Выводы о качестве правил — только при достаточном числе сигналов.
- Рентген слушает только localhost; доступ из домашней сети — позже и с паролем.
- После каждого этапа: запись в docs/decisions.md, обновление docs/progress.md и `sistema snapshot`, как только он появится.

## Переносимость
- Всё живёт в этой папке. Пути относительные, настройки и ключи — только в .env, он не попадает в git.
- data/, backups/ и chronicle/ не хранятся в git. Если подключён приватный удалённый репозиторий, код пушится в него после каждого этапа.
- База — data/sistema.db. `sistema backup` каждый день делает git bundle, копию базы и chronicle/ на внешний диск и во второе место, которое я укажу; раз в месяц проверяет, что из копии всё восстанавливается. Данные не удалять.
- `sistema install` ставит всё нужное на новом компьютере (macOS или Linux).
- `sistema serve` — один процесс: планировщик и рентген. Его держит launchd-агент на маке или systemd на Linux (`sistema autostart on`). Всё периодическое — миссии, бэкап, самоанализ — идёт через планировщик ядра.

## Команды
sistema serve · sistema autostart on|off · sistema run <миссия> · sistema events --last 1h · sistema ask "…" · sistema xray · sistema snapshot · sistema chronicle · sistema record <секунд> · sistema backup · sistema install
Все команды работают и как `uv run sistema …`.
```

## Риски и переезд

**Главные риски — сон компьютера, лимиты и выученные ошибки, и у каждого есть ответ в плане.**

| Риск | Ответ |
| --- | --- |
| Мак спит — система спит | позже переезд на Mac mini или мини-ПК, который работает круглосуточно |
| Бесплатные данные Мосбиржи идут с задержкой | для наблюдения это не мешает; реальное время — по подписке |
| Источник поменял формат | иммунитет: починка в отдельной git-ветке, тесты решают |
| Упёрся в лимит Pro | дождись сброса, этап не сгорит |
| Система выучила неправильное | отбор против случайного при достаточном числе сигналов, критик, теневой запуск |
| Сложность превращается в клубок | сезоны, журнал решений, маленькое ядро с тестами-контрактами |
| Рентген виден посторонним | сервер слушает только localhost; доступ из сети — позже и с паролем |
| Потеря компьютера или базы | три копии: мак, внешний диск (git bundle, база, chronicle/), второй хостинг или облако; проверка восстановления раз в месяц |

**Переезд на новый компьютер:** `git clone` проекта (или `git clone sistema.bundle` с внешнего диска), база и chronicle/ из бэкапа, затем `sistema install` и `sistema autostart on` — или `claude` и промпт этапа 0. Mac mini дома — лучший постоянный дом: система работает круглосуточно, а сессией Claude Code можно управлять с телефона через Remote Control, он доступен на Pro.

**Копии на всякий случай:** в git каждая копия проекта полная, со всей историей, поэтому GitHub — лишь одно из мест хранения. Держи три копии: мак, внешний диск и второй хостинг или облако.

**Что дальше после пятого сезона:** новые миссии и органы, личное пространство на локальном мозге, MCP-сервер и твой собственный код в системе, которую ты видел изнутри.
